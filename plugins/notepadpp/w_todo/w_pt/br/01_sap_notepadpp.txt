================================================================================
0. NOME E ÂMBITO
================================================================================
Definir como o **Notepad++** hospeda STATghost com o mesmo contrato chrome dos
outros hosts: nests menu/toolbar, grelha analítica lateral, checklist Config.

Este SAP é política **específica N++** (limites API, linguagem, compromissos).
A semântica das superfícies está em `shared/CHROME.md` (agnóstico de host).

STATghost continua **recetor**. O plugin nunca embute Console, Plot ou Explorer
— só dispara ações e tokens clipboard (D29).

================================================================================
1. OBJETIVO
================================================================================
 - **Terceiro host** que valida o contrato multi-editor antes de mais IDEs.
 - **Flexibilidade visual máxima** em Win32: painel dock analítico, ícones
   toolbar, diálogos com tema.
 - **Mesmo registo de ações** que `ACTION_KEYS` / `NESTS` / `grid_plan`.
 - **Performance nativa** em portáteis Windows de sala (sem dep Python para UI).

================================================================================
2. UTILIZADOR
================================================================================
Mesmo perfil **intensivo** de sala: o aluno fica no editor; menu/toolbar
compactos; separador lateral = teclado completo; Config filtra visibilidade.

Utilizadores N++ esperam fluxo Plugins — o grupo chama-se **STATghost**, nunca
"Notepad++ R".

================================================================================
3. MODELO (DECIDIDO — pendente GO owner)
================================================================================
A) **Linguagem / empacotamento**

  | Escolha             | Decisão                           |
  |---------------------|-----------------------------------|
  | Plugin produção     | **DLL Win32 Unicode** (x64) — **C++** recomendado (plugintemplate oficial); **Object Pascal** (Delphi/Lazarus) **alternativa documentada** via exports `cdecl` + [rdipardo/delphiplugintemplate](https://github.com/rdipardo/delphiplugintemplate) |
  | Distribuição        | Manifest Plugin Admin (futuro)    |
  | Spike laboratório   | PythonScript só ponte clipboard   |

  **Nota Object Pascal (2026-08-23):** manual N++ lista Delphi/Lazarus; sem
  template oficial (só C++). Comprovado (DBGp, NppCalc). Mesma ABI:
  `isUnicode`, `setInfo`, `getFuncsArray`, `beNotified`, `messageProc`.
  Docking via `TNppDockingForm` / Win32 — paridade visual com C++ se
  owner-draw ou forms VCL/LCL com tema manual (`NPPM_GETDARKMODECOLORS`).
  Owner escolhe C++ vs Lazarus no GO VP-NPP-0; contrato permanece agnóstico.

B) **Superfícies vs CHROME.md**

  | Superfície       | Mecanismo N++                         | Paridade |
  |------------------|---------------------------------------|----------|
  | Menu             | `getFuncsArray` + submenu STATghost   | 1:1      |
  | Toolbar          | `NPPM_ADDTOOLBARICON_FORDARKMODE`     | **parcial** — ícones planos; filhos só no menu |
  | Painel lateral   | `DockingDlgInterface` + owner-draw    | 1:1      |
  | Config           | Modal ou painel dock de prefs         | 1:1 semântica; UI Win32 não é árvore nativa |
  | Tema             | ponte `NPPM_GETDARKMODECOLORS`        | 1:1 intenção; theming HWND manual |

C) **Caminhos rejeitados**

  - PythonScript como host chrome principal (tema dock instável).
  - NppExec / ferramentas externas como substituto de UI.
  - Plugin ANSI (rejeitado pelo carregador N++).

D) **Importação do contrato**

  Até VP-CH-5 extrair Python para `shared/`, espelhar registo a partir de
  `chrome_show.py` via header/JSON gerado — nunca manter ordem C++ à mão.
