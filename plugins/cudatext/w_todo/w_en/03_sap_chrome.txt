================================================================================
0. NAME AND SCOPE
================================================================================
Define how **every** STATghost host exposes the same actions: menu/toolbar
nests, side analytic grid, and Config checklist — one contract, three
surfaces.

This SAP is **host-agnostic** policy. CudaText is the reference
implementation (`chrome.py`, `chrome_show.py`, `config.py`). Workbar SAP
(01) covers the Tinn-R_D → Send/Source/Inspect/Clear cut; this pack covers
**where and how** those actions render across surfaces and future editors.

STATghost stays the **receiver**. The plugin never embeds Console, Plot, or
Explorer — only triggers and clipboard tokens (D29).

================================================================================
1. GOAL
================================================================================
 - **One contract:** same `action_id`, relative order, `NESTS` tree on
   every host.
 - **Three surfaces:** menu/toolbar (synthetic nests), side panel (analytic
   grid, no nest collapse), Config (tree by domain).
 - **Gradual registry:** each new action = one entry in `chrome_show.py`
   until extract to `shared/`.
 - **Theme automatic:** bands and glyphs from editor tokens + `pick_fg_rgb`.
 - **Replication ready:** second host GO → extract contract, per-host
   adapters only.

================================================================================
2. USER
================================================================================
**Intensive** classroom: the student writes in the editor and **stays**.
Menu and toolbar stay compact (nests). The side tab is a **keypad** — every
visible action at once, grouped by family (Host, Send, Source, Inspect,
Clear, Edit). Config controls visibility without relearning ids per surface.

================================================================================
3. MODEL (DECIDED)
================================================================================
A) **Surfaces**

  | Surface          | Nest behaviour                          |
  |------------------|-----------------------------------------|
  | Menu / toolbar   | Send▾ Source▾ Inspect▾ Clear▾; collapse |
  | Side tab         | Family bands + 3-col grid; no collapse  |
  | Config           | Domain tree; `chrome.show` checklist    |

B) **Registry flow** (one new action)

  ACTION_KEYS → NESTS (if child) → GRID_GROUPS / GRID_CAP →
  DEFAULT_SHOW or `chrome.show` opt-in → host widgets.

C) **Visual language** (CudaText lab TF)

  - Bands: `_hdr_band_bg`, TabFont bold uppercase, no band icons.
  - Cells: icon + `GRID_CAP`, `icons_fg` auto contrast, hint on hover.
  - Semantic colour only on arm/host state glyphs.

D) **Theme**

  - Backgrounds from TabBg / ButtonBgPassive / TabFont tokens.
  - `pick_fg_rgb(auto)` for glyphs and captions; fallback only when tokens
    collapse.
  - Light/dark; gtk2 and Win32.

E) **Extract** (RECORD until second host GO)

  `chrome_contract`, `icons_fg`, `protocol`, `rword` → `shared/`.
  Per host: CompactChrome, AnalyticPanel, ThemeBridge.

F) **Config prefs**

  `chrome.show`, `grid_label` (below/icon/beside), `icons_fg`
  (auto/light/dark/theme), `grid_cols=3` future.

  - Copy-paste contract into each host without `shared/` extract.

================================================================================
5. RISKS
================================================================================
 - Drift: menu order ≠ grid order ≠ Config checklist.
 - gtk2 vs Win32 theme token gaps (test both).
 - Side tab mistaken for a second toolbar (must stay flat grid).
 - Premature `shared/` extract before a second host can consume it.
 - Confusing workbar SAP (Tinn cut) with chrome SAP (surface contract).
