0. NAME AND SCOPE
================================================================================
Adapt **only the essential** of Tinn-R_D's R workbar (`TBRMain`) onto the
plugin's native chrome (`chrome.py` / CudaText main toolbar).

STATghost stays the **receiver**. The plugin does **not** import the
Explorer widget, Packages, Rterm/Rgui/RHost, TCP, or a Plot pane. The
TBRMain **R control** cut (inspect the word / session hygiene) **is**
classroom comfort: click in CudaText; SG evaluates; **no** need to
switch the active window. See §3.G / VP-WB-5.

Rnoweb (Sweave / knitr) is **not** fenced out: the student can already
send R chunks and `Sweave()` / `knit()` via EVAL (EB-0 contract). What
WB-1 left out were only the TBRMain Knit/Sweave **buttons** — not the
Rnoweb classroom. See §3.F / VP-WB-4.

Umbrella: **WORKBAR**. Extension of VP-EB-1b, not a second chrome.

2. USER
================================================================================
**Intensive** classroom: the student writes in CudaText and **stays**.
They do not only send code — they inspect the identifier under the
caret (`print` / `str` / `plot` / `help`) and reset the session
(`CLEAR` / `graphics.off` / `rm`) **without** Alt-Tab to STATghost.
Console / Plot / Explorer **open in SG**; the **trigger** lives on the
plugin bar. Send/Source/Inspect/Clear extras belong in a **dropdown**,
not only behind Config.

3.F Rnoweb / Sweave / knitr — DECIDED (2026-08-16 revision)
--------------------------------------------------------------------------------
Nothing in the EB-0 contract blocks Rnoweb. STATghost evaluates **R**
(the armed engine). Send of an R selection / statement / chunk **already
works** inside a `.Rnw` / `.Rmd` (the student sends the code; SG
interprets).

**Three options — copy the Tinn-R_D cut** (real TBRMain captions;
  `actR_Send_Knit_PDF` is *Knit to LaTeX*, **not** `knit2pdf()`):

  | Button (Tinn / plugin)        | Extension         | EVAL in SG                         | Artefact → CudaText       |
  |-------------------------------|-------------------|------------------------------------|---------------------------|
  | **Sweave**                    | `.Rnw`            | `Sweave('file.Rnw')`               | `.tex`                    |
  | **Knit (LaTeX)**              | `.Rnw`            | `require(knitr); knit('…Rnw')`     | `.tex`                    |
  | **Knit (HTML)**               | `.Rmd` / `.Rhtml` | `require(knitr); knit2html('…')`   | `.html` (+ `.md` if Rmd)  |

Wrong extension → refuse with status (like Tinn: beep + message), **do
not** send. Do not merge the two Knit actions: engine (`Sweave` vs
`knit` vs `knit2html`) and product (LaTeX vs HTML) differ.

**Companion role (owner):** the plugin is **more** interesting here:

  1. **SG** interprets the EVAL above → Console echo.
  2. The **artefact** opens in **CudaText**.
  3. **Compile** `.tex` (pdfLaTeX / LuaTeX) or handle `.html` belongs to
     the **editor**. Do not embed TeX in STATghost.

The `knit2pdf` OUT does **not** remove any of the three buttons: Tinn's
“Knit PDF” **already** is `knit()` → `.tex`. `knit2pdf()` would be a
**fourth** shortcut (R runs pdflatex) — *that* duplicates step 3. Out
until an explicit GO.

Today, without a button: the student sends the EVAL by hand.
`source(.paths[4])` replaces **none** of the three — the slot is
`file.R`.

WB-4 (RECORD): Weave▾ nest with the **three** entries; after EVAL OK,
`file_open` the artefact. Noweb `<<>>=` chunks ≠ `#`/blank sniper —
later extra.

3.G R control — DECIDED (owner review 2026-08-16)
--------------------------------------------------------------------------------
Native chrome already says: *send and host commands stay in the editor
so the classroom does not bounce to STATghost*. The first WORKBAR cut
parked ls/str/plot under “Explorer”; that **misses the comfort**.

The **SG** Explorer remains the place to *browse* the environment. What
Tinn gives — and the plugin should give — is an **EVAL shortcut** from
the word under the caret, **CudaText still active**:

  | Button             | Tinn index | EVAL / command                          |
  |--------------------|-------------|-----------------------------------------|
  | Print (parent)     | 15          | identifier (Tinn Content)               |
  | ls                 | 14          | `ls()`                                  |
  | Head / Tail        | 235 / 234   | `head(x)` / `tail(x)`                   |
  | Plot               | 253         | `plot(x)` → **SG** Plot pane            |
  | Names / Str        | 16 / 17     | `names(x)` / `str(x)`                   |
  | Help (selected)    | 27          | `help(x)` (`::` package as in Tinn)     |
  | Clear (parent)     | (already)   | `#. STATGHOST:CLEAR`                    |
  | Close graphics     | 21          | `graphics.off()`                        |
  | Remove objects     | 22          | `rm(list=ls())`                         |
  | Clear all          | 23          | CLEAR + `rm(list=ls()); graphics.off()` |

No identifier (actions that need `x`): refuse with status, **do not**
send. No Plot / Explorer / ls-browser widget in CudaText.

**Out of the first cut (useful in Tinn, wrong in the companion):**
  `edit()` / `fix()` — R data editor, steals focus;
  `{ESC}` — was Rgui, not EVAL (SG interrupt = later VP);
  `example()` / open example / `help.start`;
  Packages / require / library (Tinn submenu);

Glyphs 14–17, 21–23, 27, 234, 235, 253: `png/` 16/24/32, **no tint**.
Tinn `clear_console` (20) stays in the stash (plugin Clear already has
Flaticon). Buttons = VP-WB-5 until GO.

5. RISKS
================================================================================
 - Confusing Start/Quit STATghost with Rterm/Rgui/RHost.
 - gtk2 nest: `BTN_SET_MENU` + `BTN_SET_ARROW` (PopupDropdown) — lab TF
   on Windows **and** Linux.
 - Wider default show: empty ini gains nest extras; old six-key ini has
   no arrow (document).
 - Colour Tinn glyphs vs `icons.py` tint.
 - Theme UI → reload_icons → TOOLBAR_UPDATE → theme again (flicker /
   TDR). Guard `_icons_busy` + skip if the signature did not change.
 - Config: 26 TCheckBox in a TGroupBox paint too hard on a weak GPU —
   one `checklistbox` in a compact (560px) dialog.
 - Confusing Sweave/knit (R in SG) with LaTeX compile (CudaText).
 - `source(file.R)` of a `.Rnw` buffer (noweb is not R source).
 - Confusing a `plot(x)` shortcut (EVAL) with a Plot pane in CudaText.
 - `rm(list=ls())` with no confirm — it **wipes** the workspace; Tinn
   does not ask either (keep; document the hint).
