================================================================================
0. NOME E ÂMBITO
================================================================================
Definir como **todo** host STATghost expõe as mesmas ações: ninhos
menu/toolbar, grade analítica lateral e checklist Config — um contrato,
três superfícies.

Este SAP é política **agnóstica de host**. CudaText é a implementação de
referência (`chrome.py`, `chrome_show.py`, `config.py`). O SAP workbar (01)
cobre o recorte Tinn-R_D → Send/Source/Inspect/Clear; este pack cobre
**onde e como** essas ações aparecem nas superfícies e em editores futuros.

STATghost continua **receptor**. O plugin nunca embute Console, Plot ou
Explorer — só disparadores e tokens de clipboard (D29).

================================================================================
1. OBJETIVO
================================================================================
 - **Um contrato:** mesmo `action_id`, ordem relativa, árvore `NESTS` em
   todo host.
 - **Três superfícies:** menu/toolbar (ninhos sintéticos), aba lateral
   (grade analítica, sem colapso de ninhos), Config (árvore por domínio).
 - **Registo gradual:** cada ação nova = uma entrada em `chrome_show.py`
   até extrair para `shared/`.
 - **Tema automático:** faixas e glifos a partir de tokens + `pick_fg_rgb`.
 - **Pronto para replicar:** GO do segundo host → extrair contrato; só
   adaptadores por host.

================================================================================
2. UTILIZADOR
================================================================================
Sala de aula **intensiva**: o aluno escreve no editor e **permanece** lá.
Menu e toolbar compactos (ninhos). A aba lateral é um **teclado** — cada
ação visível de uma vez, agrupada por família (Host, Send, Source, Inspect,
Clear, Edit). Config controla visibilidade sem reaprender ids por superfície.

================================================================================
3. MODELO (DECIDIDO)
================================================================================
A) **Superfícies**

  | Superfície       | Comportamento de ninho                  |
  |------------------|-----------------------------------------|
  | Menu / toolbar   | Send▾ Source▾ Inspect▾ Clear▾; colapsa  |
  | Aba lateral      | Faixas + grade 3 col.; sem colapso    |
  | Config           | Árvore por domínio; checklist chrome.show |

B) **Fluxo do registo** (ação nova)

  ACTION_KEYS → NESTS (se filho) → GRID_GROUPS / GRID_CAP →
  DEFAULT_SHOW ou opt-in `chrome.show` → widgets do host.

C) **Linguagem visual** (TF lab CudaText)

  - Faixas: `_hdr_band_bg`, TabFont negrito maiúsculas, sem ícones na faixa.
  - Células: ícone + `GRID_CAP`, contraste `icons_fg` auto, hint no hover.
  - Cor semântica só em glifos arm/host.

D) **Tema**

  - Fundos de TabBg / ButtonBgPassive / TabFont.
  - `pick_fg_rgb(auto)` para glifos e legendas; fallback só se tokens
    colapsarem.
  - Claro/escuro; gtk2 e Win32.

E) **Extrair** (REGISTO até GO do segundo host)

  `chrome_contract`, `icons_fg`, `protocol`, `rword` → `shared/`.
  Por host: CompactChrome, AnalyticPanel, ThemeBridge.

F) **Prefs Config**

  `chrome.show`, `grid_label` (below/icon/beside), `icons_fg`
  (auto/light/dark/theme), `grid_cols=3` futuro.
