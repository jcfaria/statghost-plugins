0. NOME E ÂMBITO
================================================================================
Adaptar **só o essencial** da barra R do Tinn-R_D (`TBRMain`) para o
chrome nativo do plugin (`chrome.py` / barra principal CudaText).

STATghost continua **receptor**. O plugin **não** importa o widget
Explorer, Packages, Rterm/Rgui/RHost, TCP, nem um painel Plot. O recorte
**R control** da TBRMain (inspeccionar palavra / higiene da sessão) **é**
conforto de aula: clica no CudaText; o SG interpreta; **não** precisa
alternar a janela activa. Ver §3.G / VP-WB-5.

Rnoweb (Sweave / knitr) **não** está vedado: o aluno já pode enviar
chunks R e `Sweave()` / `knit()` via EVAL (contrato EB-0). O que ficou
de fora do VP-WB-1 foram só os **botões** TBRMain Knit/Sweave — não a
aula Rnoweb. Ver §3.F / VP-WB-4.

Umbrella: **WORKBAR**. Extensão de VP-EB-1b, não um segundo chrome.

2. USUÁRIO
================================================================================
Aula **intensiva**: o aluno escreve no CudaText e **permanece** nele.
Não só envia código — inspecciona o identificador sob o cursor (`print` /
`str` / `plot` / `help`) e limpa a sessão (`CLEAR` / `graphics.off` /
`rm`) **sem** Alt-Tab para o STATghost. A Consola/Plot/Explorer **abrem
no SG**; o gatilho **vive na barra do plugin**. Extras de Send/Source/
Inspect/Clear ficam no **útil** (seta), não só no Config.

3.F Rnoweb / Sweave / knitr — DECIDIDO (revisão 2026-08-16)
--------------------------------------------------------------------------------
Nada no contrato EB-0 impede Rnoweb. STATghost avalia **R** (motor armado).
Send de selecção / statement / chunk R **já funciona** dentro de um
`.Rnw` / `.Rmd` (o aluno manda o código; o SG interpreta).

**Três opções — copiar o recorte Tinn-R_D** (captions reais da TBRMain;
  `actR_Send_Knit_PDF` chama-se *Knit to LaTeX*, **não** `knit2pdf()`):

  | Botão (Tinn / plugin)     | Extensão          | EVAL no SG                         | Artefacto → CudaText      |
  |---------------------------|-------------------|------------------------------------|---------------------------|
  | **Sweave**                | `.Rnw`            | `Sweave('ficheiro.Rnw')`           | `.tex`                    |
  | **Knit (LaTeX)**          | `.Rnw`            | `require(knitr); knit('…Rnw')`     | `.tex`                    |
  | **Knit (HTML)**           | `.Rmd` / `.Rhtml` | `require(knitr); knit2html('…')`   | `.html` (+ `.md` se Rmd)  |

Extensão errada → recusar com status (como Tinn: beep + mensagem), **não**
enviar. Não fundir os dois Knit num botão só: o motor (`Sweave` vs `knit`
vs `knit2html`) e o produto (LaTeX vs HTML) são distintos.

**Papel no companion (dono):** o plugin torna-se **mais** interessante:

  1. **SG** interpreta o EVAL acima → eco na Consola.
  2. O **artefacto** abre-se no **CudaText**.
  3. **Compilar** `.tex` (pdfLaTeX / LuaTeX) ou tratar `.html` é do
     **editor**. Não embutir TeX no STATghost.

O OUT `knit2pdf` **não** apaga nenhum dos três botões: no Tinn o “Knit
PDF” **já** é `knit()` → `.tex`. `knit2pdf()` seria um **quarto**
atalho (R chama pdflatex) — isso sim duplica o passo 3. Fora até GO
explícito.

Hoje, sem botão: o aluno envia o EVAL à mão. `source(.paths[4])` **não**
substitui nenhum dos três — o slot é `file.R`.

WB-4 (REGISTO): ninho Weave▾ com as **três** entradas; após EVAL OK,
`file_open` do artefacto. Chunk noweb `<<>>=` ≠ sniper `#`/branco —
extra posterior.

3.G R control — DECIDIDO (revisão dono 2026-08-16)
--------------------------------------------------------------------------------
O chrome.nativo já diz: *comandos de envio e de host ficam no editor
para a aula não saltar para o STATghost*. A 1.ª abordagem WORKBAR
desviou ls/str/plot para «Explorer»; isso **erra o conforto**.

O Explorer **do SG** continua a ser o sítio certo para *navegar* o
ambiente. O que o Tinn dá — e o plugin deve dar — é **atalho EVAL** a
partir da palavra sob o cursor, com o CudaText **ainda activo**:

  | Botão              | Índice Tinn | EVAL / comando                          |
  |--------------------|-------------|-----------------------------------------|
  | Print (pai)        | 15          | identificador (como Tinn Content)       |
  | ls                 | 14          | `ls()`                                  |
  | Head / Tail        | 235 / 234   | `head(x)` / `tail(x)`                   |
  | Plot               | 253         | `plot(x)` → painel Plot **do SG**       |
  | Names / Str        | 16 / 17     | `names(x)` / `str(x)`                   |
  | Help (selected)    | 27          | `help(x)` (pacote `::` como Tinn)       |
  | Clear (pai)        | (já no plugin) | `#. STATGHOST:CLEAR`                 |
  | Close graphics     | 21          | `graphics.off()`                        |
  | Remove objects     | 22          | `rm(list=ls())`                         |
  | Clear all          | 23          | CLEAR + `rm(list=ls()); graphics.off()` |

Sem identificador (acções que precisam de `x`): recusar com status,
**não** enviar. Sem widget Plot/Explorer/ls-browser no CudaText.

**Fora no 1.º recorte (úteis no Tinn, maus no companion):**
  `edit()` / `fix()` — editor R, rouba foco;
  `{ESC}` — era Rgui, não EVAL (interrupt no SG = VP futuro);
  `example()` / open example / `help.start`;
  Packages / require / library (submenu Tinn);

Glifos 14–17, 21–23, 27, 234, 235, 253: `png/` 16/24/32, **sem tint**.
`clear_console` Tinn (20) fica no stash (o Clear do plugin já tem
Flaticon). Botões = VP-WB-5 até GO.
